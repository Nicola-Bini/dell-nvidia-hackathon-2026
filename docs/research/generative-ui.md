## Report

# Generative UI for CAC: patterns to copy in 12 hours (as of 2026-10-03)

## Landscape: three tiers (CopilotKit taxonomy, Jan 29 2026)
1. **Named component + props ("static")**: AI SDK 5 (tool part `tool-<name>` mapped to a React component), Tambo 1.0 (Zod-registered components become tool definitions; MIT, self-hostable, any OpenAI-compatible provider), CopilotKit `useFrontendTool` over AG-UI, Hashbrown (`exposeComponent`, Ollama adapter).
2. **Declarative JSON constrained to a catalog**: Google A2UI (v0.9 on Apr 17 2026; v0.9.1 current, v1.0 RC; Apache-2.0; React/Lit/Angular/Flutter renderers; repo ships a Restaurant Finder sample), Vercel Labs json-render (Apache-2.0, ~18.5k stars; `defineCatalog` with Zod; flat `root` + `elements` map; JSONL RFC 6902 patch streaming), Thesys OpenUI Lang (MIT; claims up to 67% fewer tokens than JSON, -52.8% vs json-render's format).
3. **Open-ended code/HTML**: Google Generative UI / Gemini 3 "dynamic view" (Nov 18 2025), Anthropic "Imagine with Claude" (Sep 29 2025, 5-day Max preview), MCP Apps (SEP-1865 Final; launched Jan 26 2026 in Claude, Goose, VS Code Insiders, ChatGPT) and OpenAI Apps SDK: predeclared `ui://` HTML templates in sandboxed iframes talking JSON-RPC over postMessage.

## (a) Small local model: tier 1 selection inside a tier-2-shaped envelope
- **Free-form code is a frontier-model capability.** Google's paper reports output-error rates of 0% for Gemini 3 / 2.5 but 29% for Gemini 2.0 Flash and 60% for 2.0 Flash-Lite (LMArena prompts), and generation that "can often take a minute or two". Rule it out.
- **Unconstrained small models fail on syntax first.** A Sept 2026 sub-2B benchmark found only 5 of 1,000 raw responses directly parseable as JSON; the best model (Qwen2.5-1.5B) reached 75-79% tool-call success after recovery parsing.
- **Constrained decoding fixes syntax and slightly helps accuracy.** JSONSchemaBench (Llama-3.2-1B, GitHub-Easy): 65% LM-only vs 86% Guidance, 79% XGrammar, 75% llama.cpp; reasoning tasks gained 3.3-3.7 points.
- **Flat beats nested.** A2UI v0.9 moved to a flat list with a `component` discriminator because it is "much easier for LLMs to generate consistently".
- **Valid is not correct.** The Structured Output Benchmark (Apr 2026) shows near-perfect schema compliance but 83.0% value accuracy on text. So the model should emit node IDs, never values; hydrate props from the graph in code.

I found no head-to-head benchmark of the three approaches on small local models; this is triangulated.

## (b) Guaranteeing valid output locally
- **vLLM**: `response_format={"type":"json_schema",...}` or `extra_body={"structured_outputs":{json|choice|regex|grammar|structural_tag}}`; backends xgrammar, guidance, outlines, lm-format-enforcer; legacy `guided_*` fields removed in v0.12.0.
- **NIM**: `extra_body={"nvext":{"guided_json": schema}}` (also `guided_choice/regex/grammar`); XGrammar default, Outlines fallback is slow on first request; docs say avoid `json_object`.
- **llama.cpp**: `json_schema` / `response_format` compiled to GBNF; no `if/then/else`, `uniqueItems`, `patternProperties`.
- **Ollama**: `format: <schema>`, temperature 0, schema repeated in prompt. Gotcha: issue #14645 (Mar 2026), format ignored on Qwen3.5 with thinking disabled.
- Always re-validate server-side (Zod/Pydantic) and retry once with an A2UI-style `VALIDATION_FAILED` path + message.

## (c) Latency and caching
- **Output tokens dominate.** A GB10 vLLM 0.17.1 benchmark (Qwen3.6-35B-A3B-FP8) measured 21.0 tok/s at concurrency 1 (TTFT p50 363 ms), 70.2 aggregate at 8, 155.6 at 32 (TTFT p50 1,121 ms), zero failures. By my arithmetic a 40-token selection is about 2 s; a 300-token UI tree about 15 s. At concurrency 8 each stream gets roughly 10 tok/s, so caching and model-free clicks are what make "many visitors" work.
- **Semantic cache**: GPT Semantic Cache reports 61.6-68.8% hit rates with >97% positive-hit accuracy; vCache (ICLR 2026) shows static thresholds give unpredictable error rates. Key on (intent embedding, graph version); cache the selection, re-hydrate data on every hit.
- **Precompiled views**: MCP Apps predeclares templates so presentation is separated from data, "facilitating caching". Components are prebuilt React; only props travel.
- **Streaming**: json-render SpecStream and A2UI JSONL render progressively; Tambo props start `undefined`. For a 40-token answer, skip streaming and show the chosen component's skeleton.
- **Prefix reuse**: vLLM Automatic Prefix Caching reuses KV for a shared prompt prefix; put the catalog first, the visitor intent last.

## (d) Text vs component; deterministic actions
- Components carry "use when..." descriptions and the model picks (Tambo, AI SDK). Hashbrown exposes `Markdown` as a component, so text is just another catalog entry, ideal for an always-constrained schema.
- Actions bypass the model everywhere: ChatKit `ActionConfig{type,payload,handler:"server"|"client"}` with `Form` values auto-collected; A2UI `action.event{name,context}` or a client `functionCall`; json-render handlers in `defineRegistry`; MCP Apps UIs call `tools/call` over the bridge. Treat payloads as untrusted.

## (e) UX evidence
- **Against replacing nav**: NN/g (Mar 20 2026; 9 participants, 8 site chatbots including Rufus and Home Depot Magic Apron): users asked why use a chatbot when search, filters and navigation exist; bots were hard to discover, slower, more effortful. Value appeared for quick contextual questions.
- NN/g (Apr 17 2026): users treat site bots as search: short queries, scannable answers, clickable follow-ups.
- Baymard (Jul 2024): roughly 50/50 search vs navigation on general e-commerce; in apparel only 10% used search at all.
- Nielsen (2023) predicted hybrid intent + GUI; NN/g (Mar 6 2026) documents chats generating buttons and checkboxes to cut typing.
- Verdict: pitch nav + intent box, answer with components, add suggested-intent chips. No quantitative A/B data on hybrids found.

## (f) Minimal architecture
`<script src="//box/cac.js">` injects a sandboxed iframe hosting a Vite/React app.
- `POST /intent {text}`: embed, semantic cache, vector top-k over **public** nodes, one constrained LLM call, Zod validate, binder hydrates props from the graph (rejects private nodes), cache, render.
- `POST /action {name, context}`: deterministic handler (cart, booking), no LLM.

Catalog entry (owner-approved JSON):
```json
{"component":"MenuList","description":"Use when visitor asks about dishes, diets, prices","binds":["MenuItem"],"props":{"title":"string","node_ids":"MenuItem[] max 8"},"actions":{"add_to_cart":{"handler":"client"},"book":{"handler":"server"}},"goal":"bookings","status":"approved"}
```
Model output (flat, discriminated, A2UI-style):
```json
{"say":"3 vegetarian mains tonight.","views":[{"id":"v1","component":"MenuList","title":"Vegetarian","node_ids":["m12","m17"]},{"id":"v2","component":"BookingCTA"}],"gap":null}
```
Generate the JSON Schema (`oneOf` on a `component` const) from the catalog and pass it to vLLM or NIM. Flow 2 reuses the same output: text + JSON over A2A (an `application/a2ui+json` DataPart if mapped to A2UI), or an MCP App so Claude renders the widget.

## Recommendations

- Do not generate HTML/JSX with the local model. Use one constrained LLM call per typed intent that returns a tiny flat object: {say, views:[{id, component (enum from the approved catalog), node_ids, title}], gap}. Target under 60 output tokens, temperature 0, max_tokens about 120.
- Have the model emit graph node IDs only; a deterministic binder hydrates props from the knowledge graph and rejects any node not tagged public. This is both the reliability fix (valid JSON is not correct values) and the demonstrable privacy guarantee for the pitch: the model cannot place a customer name into a component.
- Generate the JSON Schema from the catalog (oneOf over a 'component' const discriminator, A2UI v0.9 style) and pass it through whatever the box serves: vLLM response_format json_schema or structured_outputs, NIM nvext.guided_json, llama.cpp json_schema, Ollama format. Still validate with Zod or Pydantic and retry once with the error path.
- Hour-0 smoke test: run about 30 restaurant intents through the schema on the actual GB10 stack; record validity rate and p50/p95 latency at concurrency 1, 4 and 8. Check that thinking mode does not disable constraint enforcement (the Ollama #14645 failure mode). Put the numbers on a pitch slide.
- Ship 6-7 prebuilt React components only: Answer (plain text, as a catalog entry per the Hashbrown pattern), MenuList, HoursCard, BookingForm, CateringQuoteForm, LocationCard, ReviewHighlights. Each catalog entry is a JSON file with component, a 'use when...' description, binds (allowed node types), props, actions, goal tag and status: approved.
- Wire every click as a ChatKit-style action {type, payload, handler: client|server} posted to /action with form values; no LLM call. Treat payloads as untrusted and re-check node visibility server-side.
- Cache in three layers: exact normalized-string match, then a semantic cache keyed on (intent embedding, graph version) with a conservative threshold, storing the selection not the data; pre-warm it by having the graph-improver sub-agent generate and precompute the top 20-30 likely intents. Demo the second visitor getting an instant answer.
- Answer the concurrency worry with architecture, not hardware: only typed novel intents reach the model, outputs are about 40 tokens, vLLM continuous batching handles simultaneous requests, and the catalog/system prompt is a stable prefix (confirm prefix caching is enabled). Quote your own measured numbers.
- Keep the existing navigation and position the intent box as an addition with 3-4 suggested-intent chips derived from owner goals (e.g., 'Book a table tonight', 'Catering quote'). Cite NN/g 2026: users treat site bots as search and want scannable answers, which is exactly what component answers deliver.
- Embed via a one-line script tag that injects a sandboxed iframe and uses postMessage for auto-resize; this isolates styles from the host site and mirrors the MCP Apps security model.
- Skip heavyweight frameworks for the 12-hour build (CopilotKit runtime, Tambo backend, full A2UI renderer). If a library is wanted, json-render (@json-render/core + @json-render/react) is the lightest catalog-to-renderer; otherwise a 50-line component registry map is enough. Borrow A2UI's vocabulary (catalog, surface, action.event) so the story maps to a Google-backed standard.
- For Flow 2, return the same {say, views, data, booking_url} payload from the agent-facing endpoint, filtered to public nodes. Stretch goal: expose it as an MCP server whose tool has _meta.ui.resourceUri pointing at the same React bundle, since Claude renders MCP Apps; mention A2UI-over-A2A (application/a2ui+json DataPart) as the roadmap mapping.
- Route unmatched intents to gap: log them into the owner's knowledge-gap report and a 'proposed new UI element' approval queue, and show that screen in the demo to cover the always-on, self-improving agent criterion.

## Open questions

- I found no published head-to-head benchmark of free-form code vs catalog-constrained JSON vs named-component tool selection on small local models; the recommendation is triangulated from the Google Generative UI paper, JSONSchemaBench, a sub-2B tool-calling benchmark and vendor design notes.
- A2UI React renderer maturity and npm package name are unclear: the April 2026 Google blog says an official React renderer shipped, but the GitHub README summary listed @a2ui/lit, @a2ui/angular and @a2ui/web_core explicitly and React less clearly. Verify before depending on it.
- Thesys C1: docs.thesys.dev now redirects to openui.com and I could not open primary C1 docs. Whether C1 can run fully local is unverified; treat it as a hosted API that would break the 'fully local' criterion. OpenUI Lang (MIT) is model-agnostic but is a non-JSON DSL, so constrained decoding would need a custom grammar.
- Which structured-output interface does the team's actual stack (NemoClaw harness plus NIM or vLLM on the GB10) expose, and does the chosen model's thinking/reasoning mode interfere with constraint enforcement? Needs a hands-on test; I did not research NemoClaw.
- The GB10 throughput numbers come from one third-party blog using a 35B MoE model at FP8; a smaller or differently quantized model will differ. My 2 s vs 15 s estimates are arithmetic from that single benchmark, not measurements.
- No quantitative A/B or conversion data was found for hybrid navigation-plus-intent-box designs on small-business sites; NN/g's 2026 studies are qualitative (n=9). Baymard's 50/50 and 10% figures are about classic site search, not AI intent boxes.
- The Nguyen, Sidorova and Torres (2022) study reporting higher cognitive load and lower autonomy for chatbots vs menu interfaces could not be opened (ScienceDirect and ACM returned 403), so it is excluded from claims.
- Semantic-cache thresholds for short restaurant intents are untested; near-duplicate but different queries (July 4th vs July 5th, enable vs disable, lunch vs dinner) are a likely false-hit class, so date/number/negation tokens may need exact-match guards.
- vLLM docs page I read states Automatic Prefix Caching must be enabled explicitly; newer builds may default differently. Check the flag on the installed version.
- Whether a consumer Claude session will discover and call a restaurant's A2A endpoint from its website without the user adding a connector is unverified; MCP Apps rendering in Claude requires the MCP server to be connected.
- OpenAI's Apps SDK docs index appeared to be reorganized under a 'plugins' naming in 2026; I confirmed the UI mechanics page but not the current official product naming.

CAVEATS ON CONFIRMED CLAIMS (matter for the spec and pitch)
- Claim 10 is the most important one to read correctly. The test used about 512 random-token input, 256 output tokens, thinking disabled. End-to-end p50 was 13.1 s at concurrency 1 and 51.6 s at 32; per-user time per output token was 48 ms (c=1), 98 ms (c=8), 195 ms (c=32). "Responsive" refers to streamed chat. It is a personal blog (Ricardo Mendes), not NVIDIA or Dell. My arithmetic from those figures: a 30-60 token "component + props" answer costs roughly 1.5-3 s at c=1 and 3-6 s at c=8, while a few-hundred-token UI tree costs 13 s or more. Output token count is the latency budget.
