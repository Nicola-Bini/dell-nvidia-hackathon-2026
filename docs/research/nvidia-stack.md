## 2. NemoClaw / OpenClaw / OpenShell
- **What**: NemoClaw (github.com/NVIDIA/NemoClaw, Apache-2.0, alpha, early preview since 2026-03-16, latest v0.0.130 on 2026-10-01) is a reference stack that runs an agent harness (OpenClaw default; also Hermes, LangChain Deep Agents) inside an NVIDIA OpenShell sandbox with managed inference.
- **Install**: `curl -fsSL https://www.nvidia.com/nemoclaw.sh | bash` then wizard (agent, runtime, model, sandbox name, channels, policy tier Balanced/Restricted/Open). NVIDIA's Spark playbook says 30-60 min for a first pass.
- **Architecture**: host `nemoclaw` CLI -> OpenShell gateway (host port 8080, credential store, L7 proxy) -> Docker sandbox confined by Landlock + seccomp + netns; writable only `/sandbox` and `/tmp`; default-deny egress; model calls go to `inference.local` and are routed by the gateway; provider keys never enter the sandbox.
- **Local models on GB10**: managed vLLM default is `nvidia/Qwen3.6-35B-A3B-NVFP4` (~25 GB) with `--gpu-memory-utilization 0.4 --max-model-len 262144 --max-num-seqs 4`. Alternatives: `--profile vllm.dgx-spark-gb10.single.nemotron-3.5-lightning-30b-a3b-nvfp4` (~21.6 GB), `NEMOCLAW_VLLM_MODEL=nemotron-3-nano-4b`, `qwen3.6-27b`; Ollama (`nemotron-3-nano:30b`); or an existing vLLM auto-detected on `localhost:8000`.
- **Useful commands**: `nemoclaw <name> status|connect|logs --follow|start|stop|recover`, `policy-add <preset>`, `channels add telegram`, `inference set`, `dashboard-url --quiet` (UI on 18789-18799), `nemoclaw tunnel start` (cloudflared), `nemoclaw onboard --agents ./agents.yaml`, `nemoclaw <name> agents apply -f ./agents.yaml --yes`.
- **Always-on**: OpenClaw "automations" (cron scheduler, `openclaw automations create|list|runs`) plus heartbeat; webhooks `POST /hooks/wake` and `/hooks/agent`. Caveat: sandboxes do not auto-restart after host reboot (start Docker, gateway, then `nemoclaw <name> connect`).
- **HTTP surface**: OpenClaw gateway offers OpenAI-compatible `POST /v1/chat/completions`, `/v1/embeddings`, `/v1/models` (off by default; `gateway.http.endpoints.chatCompletions.enabled`), `model: "openclaw/<agentId>"`. Its bearer token equals an owner credential, so never expose it to site visitors.
- **A2A**: OpenClaw ships an A2A channel plugin (A2A 1.0 JSON-RPC, Agent Card at `/.well-known/agent-card.json`, text + JSON data parts). Limits: per-peer bearer token mandatory (no anonymous mode), no streaming, 1 MiB, tasks in memory.
- **Sub-agents**: declarative `agents.yaml` (id, model, tools allow/deny, `subagents.allowAgents`), delegation via `sessions_spawn`; all agents live in one sandbox, same provider, overrides need a sandbox rebuild.
- **Maturity issues**: some model/template combos emit tool calls as plain text; vLLM `/v1/responses` skips the tool-call parser; direct DNS in the sandbox netns can fail on Spark; channels beyond Telegram/Slack/Discord vary.

## 3. Models and throughput on GB10 (published numbers)
| Model / engine | Single stream | Concurrent |
|---|---|---|
| Qwen3.6-35B-A3B NVFP4, vLLM | 97 tok/s | 322 tok/s aggregate at 8 (42/stream); ~290 with distinct prompts; 411 at 32 |
| Qwen3.6-35B-A3B FP8, vLLM (512 in / 256 out) | 21 tok/s, TTFT 363 ms | 70 at 8; 116 at 16; 156 at 32 (TTFT 1.1 s) |
| Nemotron 3.5 Lightning 30B-A3B | 72-87 tok/s Ollama Q4; 88-108 vLLM NVFP4 | not published |
| Nemotron 3 Nano 30B-A3B NVFP4 (W4A16) | 74.75 tok/s | 400 aggregate at 16 |
| gpt-oss-20b, Ollama | 58 tok/s | n/a |
| Llama 3.1 8B FP4, vLLM (StorageReview) | ~76 tok/s | up to ~2,776 tok/s batched |

- (a) Intent -> UI JSON: the 30-35B-A3B NVFP4 class with vLLM `response_format: {type: "json_schema"}` and thinking disabled. Exxact's OpenClaw tool-calling suite: qwen3.5:35b-a3b 17/17, gemma4:26b 17/17, nemotron-3-nano:30b 15/17.
- (b) Graph extraction: same model in batch; txt2kg defaults to `llama3.1:8b` (Ollama) or `nvidia/Llama-3_3-Nemotron-Super-49B-v1_5-FP8` (vLLM).
- (c) Embeddings: Qwen3-Embedding-4B (~4 GB, llama.cpp; used in NVIDIA's multi-agent chatbot playbook); bge-m3 on Ollama (used by a NYC team); NIM `nvidia/llama-nemotron-embed-vl-1b-v2` supports GB10 since Embedding NIM 2.3 (needs NGC pull).
- **Capacity estimate (mine, derived)**: at ~290-320 tok/s aggregate and ~150-token JSON answers, one box completes about 2 typed intents/s (~120/min) at ~4 s each with 8 in flight; at 16-32 in flight throughput rises to ~400 tok/s but latency passes 10 s. The NemoClaw default `--max-num-seqs 4` caps in-flight requests at 4 until raised. FP8 instead of NVFP4 cuts this roughly 4x. Since clicks are deterministic and answers cached, this supports hundreds of browsing visitors.

## Recommendations

- Confirm the deadline with organizers now: BuilderBase lists the Boston event as 2:00 PM UTC Oct 3 to 2:00 AM UTC Oct 4, which is 10 AM-10 PM EDT, not 2 PM-2 AM local; submission is via the BuilderBase portal before the deadline and only the top 8 pitch.
- Treat OpenClaw + NemoClaw + OpenShell as a required stack (stated on the SF, Seattle, NYC and Cornell pages) and make it visibly load-bearing: run `nemoclaw <name> status`, show the policy tier and a blocked egress attempt in the demo as proof of the private/public data story.
- Keep the Flow 1 hot path out of the OpenClaw agent loop: a thin host-side API should call the same local vLLM endpoint (localhost:8000) directly with response_format json_schema constrained to the owner-approved UI element catalog, thinking disabled, static system+catalog prefix first so prefix caching hits. Agent loops are prefill-heavy (Dell's lab measured about 292:1 input:output tokens) and would burn the 4 default sequence slots.
- Use NemoClaw agents for the always-on parts: one agents.yaml with main (owner-facing via Telegram), a graph-improver and a gap-reporter driven by OpenClaw automations (cron) and heartbeat, and an external-agent-facing agent with a tools allow list restricted to public-graph reads.
- Do not download a new model at the venue unless necessary: stay on whatever the box already has (NemoClaw Spark default is nvidia/Qwen3.6-35B-A3B-NVFP4, ~25 GB). If Nemotron 3.5 Lightning NVFP4 (~21.6 GB) is on disk or on a USB drive, switching to it gives a Nemotron story at similar speed.
- Raise vLLM concurrency above the NemoClaw default of --max-num-seqs 4 (to 8-16) and keep an NVFP4 checkpoint; FP8 is roughly 4x slower in aggregate. Quote in the pitch: about 97 tok/s single and about 290-320 tok/s at 8 concurrent, which is roughly 2 typed intents per second at about 4 s each, with clicks and cache hits costing zero LLM calls.
- For embeddings pick something tiny that is already local: bge-m3 or Qwen3-Embedding via Ollama/llama.cpp, or Sentence Transformers + Qdrant as txt2kg does. A restaurant graph is hundreds of nodes; do not spend time on the embedding NIM (needs NGC pull).
- Reuse txt2kg only if it starts cleanly within 30 minutes (`./start.sh --vector-search`); its WebGPU graph view on :3001 is a strong pitch visual. Otherwise store nodes with a public/private flag in SQLite or ArangoDB directly and enforce the public filter in the API layer, not in the prompt.
- For Flow 2 use OpenClaw's built-in A2A channel plugin (Agent Card at /.well-known/agent-card.json) and demo it with a second local agent or script acting as the consumer's agent; it requires a per-peer bearer token and has no streaming, and calling it from cloud Claude would undercut the fully-local criterion.
- Never expose the OpenClaw gateway token or port 18789 to the public website; the iframe panel should talk only to your own thin API, which is the single place that binds UI elements to public-tagged nodes.
- Script the recovery path (start Docker, gateway, `nemoclaw <name> connect` or `recover`) and test it once before the pitch, because sandboxes do not auto-restart after a reboot and the judges are evaluating always-on.

NEMOCLAW LIMITS THAT AFFECT THE DESIGN (item 2)
- Scope statement: NemoClaw is "an early-preview reference stack for a trusted operator on one host. It is not a hosted NemoClaw service, a multi-tenant enterprise control plane, or an enterprise identity system." Serving anonymous web visitors through it is outside its stated design. https://docs.nvidia.com/nemoclaw/user-guide/openclaw/about/overview.md
- The gateway binds to 127.0.0.1:18789 with mandatory device pairing. Widening it needs NEMOCLAW_DASHBOARD_BIND=0.0.0.0 at sandbox creation, and the docs warn this "can expose privileged gateway methods". Combined with claim 9 (bearer token equals owner credential), the OpenClaw HTTP API should not be the public endpoint for Flow 1; a thin host-side service in front is the safer shape. https://docs.nvidia.com/nemoclaw/user-guide/openclaw/security/security-controls/gateway-authentication-controls.md
- A2A (Flow 2): JSON-RPC endpoint is /a2a/v1; "There is no unauthenticated mode"; tasks live in memory (24 h, max 500) and are lost on gateway restart; file and binary parts are ignored; task cancellation, task listing and multi-tenant routing are unsupported. An arbitrary external agent such as Claude cannot call it without a pre-shared peer token. NemoClaw's own docs do not mention A2A, a generic webhook or a web-chat channel, so whether the plugin works inside the sandbox is undocumented and must be tested on the box. https://docs.openclaw.ai/channels/a2a and https://docs.nvidia.com/nemoclaw/user-guide/openclaw/manage-sandboxes/messaging-channels/choose-messaging-channels.md
- Sub-agents are not a privacy boundary: "file permissions do not isolate sub-agents from each other" (shared sandbox). The public/private pitch needs enforcement at the data layer or a separate sandbox for the external-facing agent. https://docs.nvidia.com/nemoclaw/user-guide/openclaw/configure-agents/set-up-sub-agent.md
- Always-on mechanism the researcher did not name: OpenClaw heartbeats, default every 30 minutes, set with NEMOCLAW_AGENT_HEARTBEAT_EVERY before onboarding or `openclaw config set agents.defaults.heartbeat.every 2h`, no rebuild needed. https://docs.nvidia.com/nemoclaw/user-guide/openclaw/configure-agents/configure-agent-heartbeats.md
- Reboot recovery commands: `sudo systemctl start docker`, `systemctl --user restart openshell-gateway`, `nemoclaw <name> status`, `nemoclaw <name> connect`. The headless guide says NemoClaw "does not guarantee that Docker, the OpenShell gateway, sandboxes, tunnels, or host forwards start automatically after a host reboot." https://docs.nvidia.com/nemoclaw/user-guide/openclaw/deployment/deploy-to-headless-server.md
- Plugins install at runtime: `nemoclaw <name> policy add npm_registry --yes`, then `nemoclaw <name> exec -- openclaw plugins install <pkg>`, then `nemoclaw <name> gateway restart`. https://docs.nvidia.com/nemoclaw/user-guide/openclaw/manage-sandboxes/install-openclaw-plugins.md
- Messaging channels also include Microsoft Teams and experimental Google Chat; the wizard also has Web Search (Brave) and Resource Profile steps; a fourth runtime (Pi) is now documented. https://docs.nvidia.com/nemoclaw/latest/llms.txt

MODELS AND CONCURRENCY (item 3)
- Local NIM through NemoClaw is not supported on DGX Spark: "Some NIM images do not publish a linux/arm64 manifest for DGX Spark and DGX Station." https://docs.nvidia.com/nemoclaw/user-guide/openclaw/inference/local-inference/set-up-nvidia-nim.md . A standalone NIM-LLM Spark playbook does exist (Llama 3.1 8B Instruct default, Qwen3-32B, needs an NGC key, port 8000). https://build.nvidia.com/spark/nim-llm
- Nemotron 3.5 Lightning 30B-A3B (3B active, Mamba-2 + MoE hybrid, up to 1M context, OpenMDW 1.1 licence, released 2026-08-11) is positioned for "long-running autonomous agents, sub-agent workhorse deployments" with tool calling and structured output, validated on GB10, with a DSpark speculative-decoding drafter. Its card publishes no tok/s, and the NemoClaw profile is marked Experimental. https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-NVFP4
- Embeddings were not covered. NVIDIA options: nvidia/Nemotron-3-Embed-1B-NVFP4 (1.14B params, 2048-dim, 32k tokens, vLLM 0.25.0 recommended, GB10 not in its tested-hardware list) https://huggingface.co/nvidia/Nemotron-3-Embed-1B-NVFP4 ; Nemotron-3-Embed-8B and llama-nemotron-rerank-1b-v2 also exist. NemoClaw's only documented local embedding path is Ollama qwen3-embedding:0.6b, served on host port 8000. https://docs.nvidia.com/nemoclaw/user-guide/openclaw/configure-agents/configure-memory-search.md
- Concurrency ceiling: the managed vLLM default is 4 concurrent sequences, so extra requests queue. My estimate (not a published figure): for roughly 150-250 output tokens of UI JSON called directly against vLLM, about 0.3 requests/s with FP8 numbers and about 1-2 requests/s with NVFP4 and max-num-seqs raised to 8 or more. Routing each visitor through a full OpenClaw agent turn will be much slower. I found no NVIDIA-published tok/s or concurrency figures for GB10.
- NemoClaw's Ollama path defaults to qwen3.6:35b (fallback qwen3.5:9b). https://docs.nvidia.com/nemoclaw/user-guide/openclaw/inference/local-inference/set-up-ollama.md
